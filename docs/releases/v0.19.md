# Frontile v0.19

v0.19 is the cleanup release that v0.18 promised. It removes what v0.18
deprecated, so the library stops carrying two of everything: one component
package instead of ten, and one name for each component argument.

v0.19 itself adds no new components. The 0.18.x patch releases that led up to
it did: DateInput, Stepper, an AppLayout app shell, Badge, IconButton, Icon and
Card all shipped after the v0.18.0 notes were written. If you have been pinned to 0.18.0, see
[New in the 0.18.x releases](#new-in-the-018x-releases).

If your app runs on the latest 0.18.x with no Frontile deprecation warnings in
the console, there is very little left to do.

## Before you upgrade

**Get to zero deprecation warnings on 0.18.x first.** Almost everything v0.19
removes logged a deprecation warning in 0.18.x, and each warning names its
replacement. Upgrade to the latest 0.18.x, run your app and your test suite,
and work through the warnings with the
[v0.18 migration guide](../migrations/v0.18/index.md). When the console is
clean, upgrade to v0.19.

Two removals never warned, so check for them by hand: imports of the
`FrontileStickyOptions` type (it was only marked `@deprecated`), and overlay
components rendered from `.hbs` templates (see [`.hbs` templates](#hbs-templates)).

A warning you skip on 0.18 does not turn into a warning on 0.19. It becomes a
failure, and some of those failures are silent in production (see
[What breaks, and how loudly](#what-breaks-and-how-loudly)).

## What was removed

### Packages

| Removed                                                                                                                                                     | Use instead                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `@frontile/buttons`, `@frontile/collections`, `@frontile/forms`, `@frontile/notifications`, `@frontile/overlays`, `@frontile/status`, `@frontile/utilities` | `frontile`, or a category entry point such as `frontile/forms`. These packages only re-exported from `frontile`. |
| `@frontile/forms-legacy`                                                                                                                                    | `frontile` forms. See the [Forms Legacy migration guide](../migrations/v0.18/forms-legacy.md).                   |
| `@frontile/changeset-form`                                                                                                                                  | `frontile` forms. See the [Changeset Form migration guide](../migrations/v0.18/changeset-form.md).               |

`@frontile/theme` stays. It is a separate package, not a wrapper.

The last 0.18.x release of each removed package stays on npm. They are marked
deprecated there and get no further releases.

### Component arguments

The old names of the two styling axes are gone. `@appearance` became
`@variant`, and `@intent` became `@color`, or `@status` on `FormFeedback`.

| Component                                                        | Removed                                          | Use instead                                       |
| ---------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------- |
| Button, ButtonGroup, ToggleButton                                | `@appearance`, `@intent`                         | `@variant`, `@color`                              |
| Listbox (and its Item and Group), Dropdown, Select, Autocomplete | `@appearance`, `@intent`                         | `@variant`, `@color`                              |
| Chip                                                             | `@appearance`, `@intent`, `@radius`              | `@variant`, `@color`; `Badge` for a squared label |
| Select's `@chip` options                                         | `appearance`, `intent`, `radius`                 | `variant`, `color`                                |
| CloseButton                                                      | `@onClick`; `@variant="transparent"`, `"subtle"` | `@onPress`; `"ghost"`, `"soft"`                   |
| Spinner, ProgressBar, Switch                                     | `@intent`                                        | `@color`                                          |
| FormFeedback                                                     | `@intent`                                        | `@status`                                         |

The values were renamed along with the arguments. `default` became `neutral`
on every color axis, and the variant values differ per component (Chip's
`faded` is `soft`, Listbox's `faded` is `subtle`). The
[Component API Naming guide](../migrations/v0.18/component-api-naming.md) has
the full mapping.

### Notifications

The `appearance` option is gone, along with the `NotificationAppearance` type.
Use `status`, with `danger` in place of `error` and `primary` in place of
`info`:

```js
this.notifications.add('Saved', { status: 'success' });
```

This applies to the options you pass to `add()` and to the
`'@frontile/notifications'` defaults in `config/environment.js`.

### Types and theme exports

- `FrontileStickyOptions` is gone. Use `FrontileColumnOptions`, which it was an
  alias of.
- `@frontile/theme` no longer exports the `forms-legacy` recipes (`formInput`,
  `formTextarea`, `formCheckbox`, `formRadio`, `formCheckboxGroup`,
  `formRadioGroup`, `formSelect`). The Tailwind plugin no longer styles
  `ember-power-select`, and the theme no longer depends on
  `tailwindcss-ember-power-select`. If your app still uses ember-power-select
  directly, style it in your own CSS.
- `Select` and `NativeSelect` no longer log a warning when you pass
  `@selectedKeys` in single-selection mode. The argument is still ignored
  there; use `@selectedKey`.

## What breaks, and how loudly

| If you still use                                               | What happens                                                                                                   | Fails how?                                   |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| An import from a removed `@frontile/*` package                 | The module cannot be resolved                                                                                  | Loudly, at build time                        |
| A removed argument, in a `.gts`/`.gjs` file checked by Glint   | A type error naming the unknown argument                                                                       | Loudly, at type-check time                   |
| A removed argument or option, in a development or test build   | A failed assertion that names the replacement, e.g. `Button: @appearance was removed in 0.19.0. Use @variant.` | Loudly, the first time the component renders |
| A removed argument or option, in a production build            | Ignored. The component renders with its default (see below)                                                    | **Silently**                                 |
| A `forms-legacy` recipe from `@frontile/theme`                 | The import does not exist                                                                                      | Loudly, at build or type-check time          |
| A Modal, Drawer, Popover or other overlay in a `.hbs` template | The component cannot be found (see [`.hbs` templates](#hbs-templates))                                         | Loudly                                       |

**The production row is the one to worry about.** Development assertions are
stripped from production builds, so an argument your tests never rendered
reaches production as a no-op. Most of the defaults it falls back to are
harmless, but two are not:

- **`<FormFeedback @intent="success">` renders as an error.** Without
  `@status`, FormFeedback uses its default, `danger`. The message gets error
  styling and is announced assertively to screen readers.
- **A notification created with `appearance:` renders as neutral.** The
  `status` it was meant to set is not applied, so a success or error toast
  looks like an ordinary one.

The other removed arguments fall back to the component's default variant or
color. A CloseButton given `transparent` or `subtle` renders as `ghost`.

Run your test suite against v0.19 in a development build before you ship it.
That turns every remaining use into a failed assertion.

## `.hbs` templates

In 0.18.x, `@frontile/overlays` made thirteen components resolvable by name from
classic `.hbs` templates: `Modal` and `Drawer` (with their `Body`, `Header` and
`Footer`), `Backdrop`, `Overlay`, `Popover`, `Portal` and `PortalTarget`. None
of the other wrapper packages did that. Removing `@frontile/overlays` removes
those names.

Two ways forward:

- **Move the template to `.gts` or `.gjs`** and import the component from
  `frontile`. This is the format Frontile's docs and types assume.
- **Re-export the component from your app**, one file per name, until you
  migrate:

  ```js
  // app/components/modal.js
  export { Modal as default } from 'frontile';
  ```

  Nested names live in nested files, so `<Modal::Body>` needs
  `app/components/modal/body.js` exporting `ModalBody`.

This one gave no warning on 0.18.x: a `.hbs` lookup reached the component
without going through the package's entry point, which is where its
deprecation warning lived. Search your `.hbs` templates for the names above.

No other Frontile component was ever resolvable from `.hbs` through these
packages, so nothing else changes for `.hbs` users.

## New in the 0.18.x releases

Twelve patch releases, 0.18.1 through 0.18.12, shipped between v0.18.0 and
v0.19. They added seven components and a set of enhancements, all of which
carry into v0.19 unchanged. Three of them change how existing components look
without any code change; see [Visual changes to check](#visual-changes-to-check). The version that introduced each one is in
parentheses.

### DateInput (0.18.1)

A date you type instead of pick: `mm / dd / yyyy` as separately focusable
segments, each editable with digits and arrow keys, with paste, copy and cut.
Use it where a calendar is the wrong tool, such as a birth date.
[Docs →](https://frontile.dev/docs/components/forms/date-input)

```gts preview
import { DateInput } from 'frontile';

<template>
  <div class='demo-stack'>
    <DateInput @label='Birth date' />
  </div>
</template>
```

### Stepper (0.18.7)

Progress through a multi-step flow, such as a checkout or an onboarding wizard,
with keyboard navigation, per-step loading, invalid and complete states, and a
layout that collapses to a menu at narrow widths.
[Docs →](https://frontile.dev/docs/components/navigation/stepper)

```gts preview
import { Stepper, Button } from 'frontile';

<template>
  <div class='demo-stack demo-stack--wide'>
    <Stepper @defaultValue='account' as |S|>
      <S.List @label='Checkout progress'>
        <S.Step @value='account' @title='Account' @description='Your details' />
        <S.Step @value='billing' @title='Billing' @description='Payment' />
        <S.Step @value='review' @title='Review' @description='Confirm' />
      </S.List>

      <S.Panel @value='account'>Create your account.</S.Panel>
      <S.Panel @value='billing'>Add a payment method.</S.Panel>
      <S.Panel @value='review'>Review your order.</S.Panel>

      <div class='flex gap-2'>
        <Button @variant='outline' @onPress={{S.prev}}>Back</Button>
        <Button @color='primary' @onPress={{S.next}}>Continue</Button>
      </div>
    </Stepper>
  </div>
</template>
```

### AppLayout (0.18.7)

An application shell: a collapsible Sidebar, a Navbar, the main content, an
optional Aside panel and a PageHeader, arranged for desktop and rearranged for
phones. It comes with navigation pieces (NavItem, NavFolder, NavLink) and a
BottomNav for mobile, with a "More" sheet for the items that don't fit. The
sidebar collapses to an icon rail, opens as a drawer on small screens, and
toggles with <kbd>mod</kbd>+<kbd>b</kbd>. In 0.18.8 it gained `@color` and
solid surfaces.
[AppLayout docs →](https://frontile.dev/docs/components/layout/app-layout) ·
[Sidebar →](https://frontile.dev/docs/components/layout/sidebar) ·
[BottomNav →](https://frontile.dev/docs/components/layout/bottom-nav)

### Badge (0.18.8)

A small, non-interactive label for status or metadata, with an optional value,
unit, icon or status dot. Chip stays the interactive one.
[Docs →](https://frontile.dev/docs/components/status/badge)

```gts preview
import { Badge } from 'frontile';

<template>
  <div class='flex flex-wrap gap-2'>
    <Badge>Draft</Badge>
    <Badge @color='primary' @value={{12}}>Open</Badge>
    <Badge @color='success' @value='$49' @unit='/mo'>Pro</Badge>
  </div>
</template>
```

### IconButton (0.18.12)

A button that shows only an icon, drawn as a circle as tall as a Button of the
same size. It takes Button's sizes, colors and variants, and the icon is the
block you pass in, so any icon source works. `@label` gives it its accessible
name. [Docs →](https://frontile.dev/docs/components/buttons/icon-button)

```gts preview
import { IconButton } from 'frontile';
import { DeleteIcon } from 'site/components/icons';

<template>
  <IconButton @label='Delete item'><DeleteIcon /></IconButton>
</template>
```

### Icon (0.18.12)

Sizes an icon on the same ramp as Button's label text, and can put it in a
circle. Like IconButton, it takes the icon as a block.
[Docs →](https://frontile.dev/docs/components/utilities/icon)

```gts preview
import { Icon } from 'frontile';
import { StarIcon } from 'site/components/icons';

<template>
  <p class='flex items-center gap-2 text-primary-strong'>
    <Icon @size='xs'><StarIcon /></Icon>
    Starred
  </p>
</template>
```

### Card (0.18.12)

A surface for grouping content: a fill, a border, rounded corners and padding,
with no regions of its own. What goes inside is up to you.
[Docs →](https://frontile.dev/docs/components/utilities/card)

```gts preview
import { Card } from 'frontile';

<template>
  <div class='demo-stack'>
    <Card>
      <p class='text-neutral-bolder font-semibold'>Card title</p>
      <p class='text-neutral-firm text-sm'>
        Anything can go here. Card only supplies the surface.
      </p>
    </Card>
  </div>
</template>
```

### Enhancements

- **Button** gained two variants (0.18.12): `glass`, a translucent scrim for
  buttons over a colored or image background, and `link`, ink only with no
  fill or side padding, so it lines up with the text around it.

- **DatePicker** renders the DateInput segments as its trigger by default, so
  a date can be typed or picked (0.18.1); `@isEditable={{false}}` restores the
  button trigger. It also gained time segments with `@granularity` (0.18.2)
  and an hour and minute list beside the calendar (0.18.6).
- **DatePicker, DateInput, Calendar and Pagination** labels are translatable
  (0.18.2, 0.18.3).
- **Select and Autocomplete** take `@displayLimit` to cap how many options
  they render (0.18.5).
- **Avatar** gained `@fit` for logos and `@isBordered`, and falls back to the
  initials when the image fails to load (0.18.1).
- **Chip** gained an `xs` size (0.18.1) and is always a pill; `@radius` was
  deprecated in 0.18.8 and is removed in v0.19.
- **Popover** fits the viewport and renders as an inset card on small screens
  (0.18.11).
- **Theme**: nested `light`, `dark` and `theme-inverse` scopes resolve from
  the nearest ancestor (0.18.8), and `size-icon-*` utilities follow the label
  text sizes (0.18.12).

### Visual changes to check

These shipped in patch releases and need no code change, but they change how
your app looks. If you are coming from an earlier 0.18.x, look for them:

- **Avatar has no ring by default** (0.18.1). Pass `@isBordered={{true}}` to
  keep the old look.
- **Every Button moved down one size** (0.18.11), so an unsized `<Button>` gets
  smaller. Move `@size` up one step to keep a button where it was. The neutral
  color's ink and soft fills changed too. See the
  [v0.18.11 notes](./v0.18.md#v01811-button-sizes-change).
- **Badge and Chip use Button's size names and default to `xs`** (0.18.12), so
  chips and badges, including the chips in a multiple Select, render at
  different sizes than before. A new `2xs` matches the old small sizes. See
  [Badge and Chip share Button's sizes](../migrations/v0.18/index.md#8-badge-and-chip-share-buttons-sizes--default-is-now-xs).

Each release's full list of changes is on
[GitHub](https://github.com/josemarluedke/frontile/releases).

## Upgrading from v0.17 or earlier

Upgrade to the latest 0.18.x first, follow the
[v0.18 migration guide](../migrations/v0.18/index.md), and then come back here.
Jumping straight to v0.19 skips the deprecation warnings that tell you what
to change.
